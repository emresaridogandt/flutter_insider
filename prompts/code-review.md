## Architecture Patterns

**Platform Channel Bridge.** Every feature crosses three layers that must stay in lockstep:

```
Dart public method  →  Constants.X  →  MethodChannel('flutter_insider')
                                            ↓
                         Java: case Constants-equivalent string in onMethodCall switch
                         Obj-C: [call.method isEqualToString:@"..."] in handleMethodCall:
```

There is **no compile-time link** between the three sides. A name that matches on two sides and not
the third produces a silent runtime no-op: no exception, no test failure, no crash. This is the
single highest-value thing to check in this repository.

## Security Requirements

- **Never log or forward PII.** User attributes (`setEmail`, `setPhoneNumber`, `setName`, custom
  attributes) flow through this plugin. They must not be written to logcat/NSLog, printed via
  `print()`/`debugPrint`, or embedded in exception messages sent through `putException`.
- **`putException` sends its payload to the Insider backend.** Anything interpolated into an
  exception string leaves the device. Flag any `putException` call that includes user attribute
  values, tokens, or endpoint credentials.
- **Custom endpoints** (`initWithCustomEndpoint`) must be treated as untrusted input from the host
  app — never string-concatenated into anything that reaches a shell or a file path.
- **No secrets in the repo.** `android/build.gradle`, `ios/flutter_insider.podspec`, and workflow
  files must not carry tokens. A committed secret is compromised even if a later commit removes it.
- **GDPR**: `setGDPRConsent` gates data collection. Changes to consent handling, or to any collection
  toggle (`enableIDFACollection`, `enableIpCollection`, `enableLocationCollection`,
  `enableCarrierCollection`), are high-severity and need explicit justification in the PR.

## Common Bug Patterns

### 1. Wire-contract drift across the three layers (CRITICAL)

A new or renamed constant in `lib/src/constants.dart` must land in **both** natives.

```dart
// ❌ Dart-only change — silently does nothing on both platforms
static const String SET_NEW_THING = "setNewThing";
```

Verify the PR also touches `FlutterInsiderPlugin.java` (a new `case`) and `FlutterInsiderPlugin.m`
(a new string comparison). If it does not, that is a blocking finding. The reverse also applies: a
native handler with no Dart constant is dead code.

### 2. Custom-parameter type tags (CRITICAL)

`FlutterInsiderUtils.serializeCustomParameters()` emits `[{type, key, value}]`. Both natives'
`convertCustomParameters()` parse those `type` strings. Valid tags:

`string`, `integer`, `double`, `boolean`, `date` (epoch millis), `string_array`, `numeric_array`

Renaming, adding, or reordering a tag on one side only breaks deserialization at runtime with no
compile error.

### 3. `catch (Exception)` shadows the Dart core type

The codebase names catch parameters `Exception`, which shadows `dart:core`'s `Exception` type:

```dart
// ❌ Do not write this in new code
} catch (Exception) {
  FlutterInsiderUtils.putException(channel, Exception);
}

// ✅ Preferred
} catch (e) {
  FlutterInsiderUtils.putException(channel, e);
}
```

This appears in **75 of 131** existing `putException` call sites. It is legacy and *works* — the
name merely shadows the type. **Flag it only in newly added or modified code.** Do not raise it on
untouched lines, and do not ask for a repo-wide cleanup in an unrelated PR.

### 4. Swallowed errors

`putException` is fire-and-forget and never rethrows. A `catch` that calls it and then returns
`null` hides the failure from the host app. That is the established pattern here, so do not flag it
by default — but do flag it when the swallowed failure would leave the SDK in an inconsistent state
(e.g. a partially built product/event payload still being sent).

### 5. Enum parsing without a fallback

`InsiderAppCardsError.fromMap` uses `asNameMap()[rawCode] ?? InsiderAppCardsErrorCode.unknown`.
Any new native error code must be added to the enum, and any new parsed enum must keep an
`unknown`-style fallback — otherwise an unrecognised native string throws at runtime.

### 6. Version drift across four locations

The plugin version lives in **four** places, not three:

| Location | Form |
|---|---|
| `pubspec.yaml` | `version: 5.2.0` |
| `android/build.gradle` | `5.2.0-SNAPSHOT` |
| `ios/flutter_insider.podspec` | `5.2.0` |
| `lib/flutter_insider.dart` → `initFlutterBase` | `args["sdkVersion"] = "F-5.2.0"` |

`devops/update_version_number.sh` maintains these. A PR that bumps some but not all leaves the SDK
reporting a stale version to the backend forever, silently. `CLAUDE.md` documents only the first
three — the `F-` literal is the one that gets forgotten.

### 7. Native iOS pins differ per channel

`ios/flutter_insider.podspec` pins exact native versions (bumped by `devops/update_version_number.sh`
from `pod trunk`). `ios/flutter_insider/Package.swift` deliberately does not: it depends on
`useinsider/Insider-iOS-SDK` with `branch: "main"`, so SwiftPM consumers follow that package's
`main`. Do not flag the `branch:` dependency or a podspec/SwiftPM version mismatch — both are
decisions. Flag a change that introduces a `binaryTarget`, a checksum, or an `exact:` pin into the
manifest without a matching decision.

## Business Logic Rules

- **Init ordering**: most methods are no-ops until `init`/`initWithCustomEndpoint` has run. New
  public methods should degrade safely when the SDK is uninitialised, not throw.
- **Identifiers**: `login`/`logout` and message-center identifiers change user identity. Review
  changes here for cross-user data leakage (attributes retained across a logout).
- **Product/event builders**: required fields (`productID`, `name`, `taxonomy`, `imageURL`, `price`,
  `currency`) must remain required; making one optional is a silent payload-shape change.
- **App Cards**: the only API surface with structured typed errors. New App Cards methods should use
  `InsiderAppCardsException`, not the fire-and-forget `putException` path.

## Performance Considerations

- Platform-channel calls are async and cross a serialization boundary. Flag calls placed inside
  `build()` methods, tight loops, or scroll handlers.
- `lib/flutter_insider.dart` is the hot file (167 historical changes). Large additions here warrant
  a check on whether the logic belongs in a `lib/src/` domain class instead.
- Custom-parameter maps are serialized on every tagged event; avoid building large maps per call.

## Dependencies

> **Do not flag a missing CHANGELOG entry for native SDK version bumps.** Native versions in
> `android/build.gradle` and `ios/flutter_insider.podspec` are resolved to the latest published
> release by `devops/update_version_number.sh` as part of the automated release process. They are
> intentionally **not** required in `CHANGELOG.md`, and their absence there is not a finding —
> regardless of whether an earlier release happened to mention one. Review the bump itself if you
> like; do not raise the release note.

- The plugin ships with **no third-party Dart dependencies** — only `flutter` and `flutter_test`.
  Adding a runtime dependency to `pubspec.yaml` is a significant decision for a published plugin
  (it propagates to every host app) and needs explicit justification.
- Native SDK bumps in `android/build.gradle` / `ios/flutter_insider.podspec` carry real behavioural
  risk and cannot be covered by this repo's tests. Confirm the PR notes device smoke-testing.
- `devops/api_surface_check/requirements.txt` covers CI tooling only; it does not ship.

## Review Checklist

- [ ] New/renamed `Constants.*` entries have matching handlers in **both** `FlutterInsiderPlugin.java` and `FlutterInsiderPlugin.m`

- [ ] Dart changes have a corresponding wire-contract test (see `prompts/test-coverage.md`)
- [ ] New enums parsed from native payloads keep an `unknown` fallback
- [ ] Consent/collection toggles unchanged, or the change is justified in the PR body

## Severity Guidelines

| Severity | Use for |
|---|---|
| **Critical** | Wire-contract drift; custom-parameter type-tag change; PII leaving the device; consent/GDPR regression; removed or signature-broken public API |
| **High** | Missing native handler on one platform; enum parsed with no fallback; partial version bump; swallowed error leaving inconsistent state |
| **Medium** | Missing test for a new wire contract; inline method-name string instead of `Constants.*`; new required builder field |
| **Low** | Naming, comment accuracy, `catch (Exception)` in newly added code, formatting |

Prefer few high-confidence findings over many speculative ones. Do not raise findings on lines the
PR did not touch.
