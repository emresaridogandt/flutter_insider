## Language & SDK Constraints

- SDK constraint: `>=2.15.0 <4.0.0`, Flutter `>=2.8.0`. **Null safety is on.**
- This is a **published package**. Every symbol exported from `lib/flutter_insider.dart` is public
  API for host apps. Treat signature changes as breaking unless proven otherwise.
- No third-party runtime dependencies. Do not approve new ones without explicit justification.

## Null Safety & Optionality

- Prefer explicit nullable types (`String?`) over `dynamic`. `dynamic` appears in legacy payload
  maps; do not propagate it into new code.
- Adding a **required** parameter to an existing public method is breaking. Add optional named
  parameters with defaults instead.
- Watch for `!` (bang) on values that originate from a platform channel — native payloads are
  untrusted at the type level. Prefer `as X?` plus a fallback:

```dart
// ❌ throws if native omits the key
final code = map['code']! as String;

// ✅ established pattern in lib/src/app_cards_error.dart
final rawCode = map['code'] as String? ?? 'unknown';
```

## Platform Channel Correctness

- **Always** reference method names via `Constants.*`. An inline string literal is a Medium finding
  even when correct, because it defeats the constants-parity check.

```dart
// ❌
await _channel.invokeMethod('setName', args);

// ✅
await _channel.invokeMethod(Constants.SET_NAME, args);
```

  Known legacy literals — flag them only on a line the PR touches, never as a regression: the
  `appCardsMarkAsRead`, `appCardsMarkAsUnread`, `appCardsDelete`, `viewAppCard`, `clickAppCard`,
  `clickAppCardButton` calls in `lib/src/insider_app_cards.dart` and the `putException` call in
  `lib/src/utils.dart`.

- Argument maps must be `Map<String, dynamic>`. Keys are part of the wire contract — renaming one
  requires the matching change in both natives.
- `invokeMethod` returns `Future`. An un-awaited call in a method that reports success is a real
  bug: flag `invokeMethod` without `await` or an explicit `unawaited()`.
- Methods that return values to callers should use `invokeMethod<T>` and handle a `null` return
  (the native side returns `nil`/`null` when uninitialised).

## Error Handling

Two distinct paths exist. Use the right one:

| Path | Use for | Behaviour |
|---|---|---|
| `FlutterInsiderUtils.putException(channel, e)` | Legacy/most methods | Fire-and-forget report to native; never rethrows; caller sees `null`/no-op |
| `InsiderAppCardsException` + `InsiderAppCardsError` | App Cards only | Structured, typed `InsiderAppCardsErrorCode`; caller can branch |

Rules:

- New **App Cards** methods must use the structured path.
- New code must use `catch (e)`, never `catch (Exception)` — see `prompts/code-review.md` §3. The
  75 existing occurrences are legacy; do not flag untouched lines.
- Never interpolate user attribute values into the exception string — `putException` sends it off
  device.
- A `catch` that returns `null` and logs nothing is acceptable here *only* because it is the
  house pattern. Flag it when the caller cannot distinguish "no data" from "failed".

## Idioms Specific to This Codebase

- **Singleton facade**: `FlutterInsider.Instance`. Do not add a second entry point or a competing
  static accessor.
- **Builders** (`FlutterInsiderUser`, `FlutterInsiderProduct`, `FlutterInsiderEvent`) take the
  `MethodChannel` by constructor injection — this is what makes them testable. Preserve it; do not
  reach for a global channel inside a builder.
- **`lib/enum/*.dart` are constant-holder classes**, not Dart `enum`s — `static const int` members
  such as `InsiderGender.MALE`. Genuine enums with logic (e.g. `InsiderAppCardsErrorCode` with
  `fromMap`) live in `lib/src/`. Do not "modernise" the former into real enums: the integer values
  are the wire contract with the natives.
- **`FlutterInsiderUtils.getDateForParsing`** renders a `DateTime` as ISO-8601 with a `Z` suffix
  while preserving local wall-clock time. That is deliberate. Changing it to true UTC conversion
  shifts every date attribute already stored in the backend.

## Anti-Patterns to Catch

| Anti-pattern | Why it matters here |
|---|---|
| Inline method-name string instead of `Constants.*` | Breaks the parity check that guards the bridge |
| `print()` / `debugPrint()` of user attributes | PII leaves the app's logs |
| Un-awaited `invokeMethod` in a method that reports success | Silent failure |
| New required parameter on a public method | Breaks host apps at compile time |
| Widening a builder's required-field set | Silent payload-shape change |
| `catch (Exception)` in new code | Shadows `dart:core` `Exception` |
| Adding a runtime dependency to `pubspec.yaml` | Propagates to every host app |
| Converting `lib/enum/*` const classes to real enums | Integer values are the native wire contract |

## Performance

- Platform-channel round trips are not free. Flag `invokeMethod` inside `build()`, `ListView`
  builders, scroll listeners, or loops over collections.
- `serializeCustomParameters` allocates a list of maps per call — avoid rebuilding large parameter
  maps on every event when a cached map would do.
- `lib/flutter_insider.dart` is ~993 LOC and the repo's most-changed file. Large additions should
  be questioned: does this belong in a `lib/src/` domain class?

## Documentation

- Public API members carry dartdoc (the package publishes documentation to pub.dev). A new public
  method without a `///` comment is a Low finding; a new *public class* without one is Medium.
- Dartdoc references (`[FlutterInsiderUser.setGender]`) must resolve — a broken reference degrades
  the published docs.
